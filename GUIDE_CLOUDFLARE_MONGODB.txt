অধ্যায় ১: কেন আগে কাজ করেনি? (Why It Did NOT Work Earlier)
--------------------------------------------------------------------------------
আমরা প্রথমে যখন @opennextjs/cloudflare এবং Cloudflare Pages ব্যবহার করে কাজ 
করতে যাচ্ছিলাম, তখন একের পর এক সমস্যা হচ্ছিল। এর পেছনে ৪টি গভীর টেকনিক্যাল 
কারণ ছিল:

১. Cloudflare Pages-এর আউটবাউন্ড TCP পোর্ট ব্লকেজ (সবচেয়ে বড় কারণ):
-----------------------------------------------------------------------
* সমস্যা: MongoDB Atlas ডাটাবেসের সাথে যোগাযোগ করার জন্য নোডজেএস TCP 
  সকেট ব্যবহার করে (পোর্ট: 27017)।
* কেন ফেইল করেছিল: Cloudflare Pages-এর আর্কিটেকচার মূলত স্ট্যাটিক সাইট ও 
  সাধারণ HTTP রিকোয়েস্টের জন্য অপ্টিমাইজড। এর Functions রানটাইমে আউটবাউন্ড 
  TCP সকেটের পোর্ট ২৭০১৭ ক্লাউডফ্লেয়ারের নেটওয়ার্ক লেভেলে ব্লক/ড্রপ করা থাকে।
* এরর মেসেজ: আপনি বারবার যে এররটি দেখছিলেন:
    Socket 'secureConnect' timed out
    MongoServerSelectionError: Server selection timed out after 30000 ms
  যতক্ষণ অ্যাপটি Cloudflare Pages-এ চলছিল, ততক্ষণ MongoDB-র সাথে কোনোভাবেই 
  কানেক্ট হওয়া সম্ভব ছিল না।

২. Serverless সকেট ক্যাশিং বাগ (global._mongoClientInstance):
-------------------------------------------------------------
* সমস্যা: সাধারণ Node.js/Express সার্ভারে মেমরিতে MongoClient কানেকশন 
  গ্লোবালি ক্যাশ করে রাখা হয় যাতে প্রতি রিকোয়েস্টে নতুন হ্যান্ডশেক না করতে হয়।
* কেন ফেইল করেছিল: Cloudflare Workers-এর মতো এজ সার্ভারলেস আইসোলেটে একটি 
  ইনভোকেশন শেষ হলে ব্যাকগ্রাউন্ড সকেট ক্লাউডফ্লেয়ার সাময়িকভাবে ফ্রিজ বা বন্ধ 
  করে দেয়। ফলে গ্লোবাল ক্যাশ করা মঙ্গো ক্লায়েন্ট পরবর্তী রিকোয়েস্টে ওই 
  ডেড/ক্লোজড সকেট ব্যবহার করার চেষ্টা করত এবং бесконечно হ্যাং হয়ে থাকত।

৩. Pages-এ _worker.js আর্কিটেকচারাল অসঙ্গতি:
------------------------------------------
* সমস্যা: Cloudflare Pages Advanced মোডে ডিপ্লয় করতে হলে আউটপুট ফোল্ডারে 
  একটি একক মনোলিথিক _worker.js ফাইল থাকতে হয়।
* কেন ফেইল করেছিল: আধুনিক Vite/Vinext ফ্রেমওয়ার্ক ফাইল সাইজ ও লোডিং ফাস্ট 
  রাখার জন্য কোড-স্প্লিটিং (Code-Splitting) করে একাধিক .js ফাইল তৈরি করে। 
  Cloudflare Pages-এর বিল্ডার এই মাল্টি-ফাইল বান্ডেল সাপোর্ট করে না এবং এরর 
  দিয়ে বিল্ড আটকে দেয়:
    X [ERROR] _worker.js is not being bundled by Wrangler but it is 
    importing from another file.

৪. dist/client-এ index.html না থাকায় ব্ল্যাঙ্ক বা 404 পেজ আসা:
-------------------------------------------------------------
* সমস্যা: Next.js হলো একটি Server-Side Rendered (SSR) অ্যাপ্লিকেশন, এটি 
  কোনো পিওর স্ট্যাটিক এইচটিএমএল সাইট নয়।
* কেন ফেইল করেছিল: vinext build দেওয়ার পর dist/client ফোল্ডারে শুধু CSS 
  ও জাভাস্ক্রিপ্ট চাঙ্ক তৈরি হয়, কিন্তু কোনো index.html ফাইল থাকে না (কারণ 
  পেজ সার্ভার থেকে রেন্ডার হয়ে আসার কথা)। যখন Cloudflare Pages-এ আউটপুট 
  হিসেবে dist/client দেওয়া হয়, Pages কোনো index.html না পেয়ে সরাসরি 
  404 Not Found বা সম্পূর্ণ ব্ল্যাঙ্ক স্ক্রিন প্রদর্শন করত।


--------------------------------------------------------------------------------
অধ্যায় ২: কেন এখন সফলভাবে কাজ করছে? (Why It Works Now)
--------------------------------------------------------------------------------
আমরা প্রজেক্টটিকে Cloudflare-এর আধুনিক স্ট্যান্ডার্ড "vinext + Cloudflare 
Workers with Assets"-এ মাইগ্রেট করেছি, যা সমস্ত প্রতিবন্ধকতা দূর করেছে:

১. Cloudflare Workers-এর নেটিভ আউটবাউন্ড TCP সাপোর্ট:
----------------------------------------------------
* Cloudflare Workers-এ nodejs_compat মোড সক্রিয় থাকায় এটি ক্লাউডফ্লেয়ারের 
  নেটিভ connect() সকেট এপিআই ব্যবহার করতে পারে।
* ফলে পোর্ট ২৭০১৭ দিয়ে সরাসরি MongoDB Atlas-এর প্রাইমারি শার্ডে কোনো রকম 
  ব্লক বা টাইমআউট ছাড়াই মাত্র ৭০০-১১০০ মিলিসেকেন্ডে কানেকশন তৈরি হয়।

২. আধুনিক vinext আর্কিটেকচার:
----------------------------
* Cloudflare-এর নিজস্ব Vite-ভিত্তিক ফ্রেমওয়ার্ক vinext পুরো Next.js App 
  Router (SSR, Layout, Server Components, API Routes) নিখুঁতভাবে কম্পাইল করে।
* এটি dist/server/index.js (সার্ভার হ্যান্ডলার) এবং dist/client (স্ট্যাটিক 
  অ্যাসেট)-কে Workers-এর সাথে চমৎকারভাবে ইন্টিগ্রেট করে।

৩. সার্ভারলেস-বান্ধব MongoDB আর্কিটেকচার (lib/mongodb.ts):
---------------------------------------------------------
* প্রতি সার্ভারলেস ইনভোকেশনে কোনো ডেড সকেট ক্যাশ না রেখে সরাসরি ফ্রেশ 
  লাইটওয়েট কানেকশন তৈরি করা হয়।
* অপ্টিমাইজড কনফিগারেশন:
  - directConnection: true — সরাসরি প্রাইমারি শার্ডে কানেক্ট হয় (অপ্রয়োজনীয় 
    DNS লুকআপ ও ইন্টারনাল রাউটিং স্কিপ করে)।
  - tls: true — সিকিউর এনক্রিপশন নিশ্চিত করে।
  - family: 4 — শুধুমাত্র IPv4 ব্যবহার করে (Edge-এ IPv6 ডিলে রোধ করে)।
  - maxPoolSize: 1, minPoolSize: 0 — সার্ভারলেস আইসোলেটের মেমোরি ও সকেট 
    লিক সম্পূর্ণ রোধ করে।

৪. Cloudflare Workers Git Integration:
-------------------------------------
* Pages বাদ দিয়ে প্রজেক্টটি ড্যাশবোর্ডের Workers সেকশনে কানেক্ট করা হয়েছে।
* Workers প্রজেক্টের wrangler.jsonc ফাইলটি সরাসরি রিড করতে পারে এবং 
  dist/client থেকে স্ট্যাটিক ফাইল ও dist/server থেকে লাইভ SSR পেজ ও API 
  নিখুঁতভাবে পরিচালনা করে।

অধ্যায় ৩: প্রজেক্ট কনফিগারেশন ফাইলসমূহ (Reference)
--------------------------------------------------------------------------------

১. wrangler.jsonc (Cloudflare Workers কনফিগারেশন):
--------------------------------------------------
{
  "name": "next-cloud-mongodb",
  "compatibility_date": "2026-09-08",
  "compatibility_flags": [
    "nodejs_compat"
  ],
  "main": "vinext/server/fetch-handler",
  "assets": {
    "directory": "dist/client",
    "not_found_handling": "none",
    "binding": "ASSETS"
  },
  "cache": {
    "enabled": true
  },
  "version_metadata": {
    "binding": "CF_VERSION_METADATA"
  }
}

২. vite.config.ts (Vinext বিল্ডার কনফিগারেশন):
----------------------------------------------
import { cloudflare } from "@cloudflare/vite-plugin";
import { defineConfig } from "vite";
import vinext from "vinext";

export default defineConfig({
  plugins: [
    vinext(),
    cloudflare({
      configPath: "./wrangler.jsonc",
    }),
  ],
});

৩. package.json স্ক্রিপ্টসমূহ:
----------------------------
"scripts": {
  "dev": "next dev",
  "build": "vinext build",
  "dev:vinext": "vinext dev",
  "build:vinext": "vinext build",
  "preview:vinext": "wrangler dev",
  "deploy:vinext": "vinext-cloudflare deploy --config dist/server/wrangler.json"
}

অধ্যায় ৪: নতুন প্রজেক্ট ডেপ্লয়মেন্টের চেকলিস্ট
--------------------------------------------------------------------------------
ভবিষ্যতে একই রকম Next.js + MongoDB প্রজেক্ট Cloudflare-এ ডিপ্লয় করতে 
নিচের সহজ ধাপগুলো অনুসরণ করুন:

ধাপ ১: MongoDB Atlas নেটওয়ার্ক অ্যাক্সেস (IP Whitelist):
---------------------------------------------------------
1. MongoDB Atlas Dashboard (https://cloud.mongodb.com)-এ লগইন করুন।
2. Security ➔ Network Access-এ যান।
3. Add IP Address বাটনে ক্লিক করুন।
4. Allow Access from Anywhere (0.0.0.0/0) সিলেক্ট করে Save করুন 
   (কারণ Cloudflare এজ আইপি প্রতিনিয়ত ডায়নামিকভাবে পরিবর্তিত হয়)।

ধাপ ২: Cloudflare ড্যাশবোর্ড সেটআপ:
-----------------------------------
1. Cloudflare Dashboard (https://dash.cloudflare.com)-এ যান।
2. বাম পাশের মেনু থেকে Workers & Pages-এ ক্লিক করুন।
3. Create application বাটনে ক্লিক করুন।
4. Workers ট্যাব সিলেক্ট করুন (ভুলেও Pages ট্যাব সিলেক্ট করবেন না)।
5. Connect to Git সিলেক্ট করে আপনার গিটহাব রিপোজিটরি বেছে নিন।
6. কনফিগারেশন দিন:
   - Project Name: আপনার ইচ্ছামতো নাম (যেমন: next-cloud-mongodb)
   - Build command: npm run build:vinext
   - Deploy command: npx wrangler deploy
7. Environment variables-এ যোগ করুন:
   - MONGODB_URI = আপনার MongoDB Atlas কানেকশন স্ট্রিং
   - MONGODB_DB = next_cloud_db
8. Deploy বাটনে ক্লিক করুন!

অধ্যায় ৫: গুরুত্বপূর্ণ কমান্ড চিটশীট
--------------------------------------------------------------------------------
* লোকাল Next.js ডেভেলপমেন্ট সার্ভার চালু করতে:
  npm run dev (পোর্ট: localhost:3000)

* লোকাল Vinext ডেভেলপমেন্ট সার্ভার চালু করতে:
  npm run dev:vinext

* প্রজেক্ট প্রোডাকশন বিল্ড করতে:
  npm run build:vinext

* লোকাল ক্লাউডফ্লেয়ার এজ রানটাইমে টেস্ট করতে:
  npx wrangler dev --port 8787

* কোড টাইপচেক ভেরিফাই করতে:
  npx tsc --noEmit

* CLI দিয়ে সরাসরি ক্লাউডফ্লেয়ার Workers-এ ডিপ্লয় করতে:
  npm run deploy:vinext
