অধ্যায় ১: মূল আর্কিটেকচার ও উভয় প্ল্যাটফর্মে কাজ করার কৌশল
--------------------------------------------------------------------------------
এই প্রজেক্টটিকে এমনভাবে আর্কিটেকচার করা হয়েছে যাতে কোডের কোনো পরিবর্তন ছাড়াই এটি 
Cloudflare-এর দুটি ভিন্ন প্ল্যাটফর্মেই নির্বিঘ্নে চলতে পারে:

১. Cloudflare Pages:
   - স্ট্যাটিক সাইট এবং D1-ভিত্তিক ফ্রন্টএন্ড চালানোর জন্য আদর্শ।
   - এখানে বিল্ড সেটিংস নির্দিষ্ট থাকে: Build command: npm run build:cloudflare 
     এবং Build output directory: out।
   - Pages Advanced Mode ব্যবহার করে out ফোল্ডারের ভেতরে _worker.js ডিরেক্টরি 
     তৈরি করা হয়, যা স্বয়ংক্রিয়ভাবে ক্লাউডফ্লেয়ার এজ ফাংশন হিসেবে রান করে।

২. Cloudflare Workers:
   - উচ্চ পারফরম্যান্স মাইক্রোসার্ভিস ও ব্যাকএন্ড API-র জন্য আদর্শ।
   - কোনো out ফোল্ডার লাগে না; সরাসরি wrangler.jsonc থেকে dist/client (অ্যাসেট) 
     এবং dist/server (ওয়ার্কার হ্যান্ডলার) রিড করে গ্লোবাল এজে রান করে।


--------------------------------------------------------------------------------
অধ্যায় ২: Cloudflare Pages-এ যেভাবে কাজ করে (Out Directory Setup)
--------------------------------------------------------------------------------
Cloudflare Pages ডিপ্লয় করার সময় বিল্ড সিস্টেম একটি নির্দিষ্ট আউটপুট ফোল্ডার (out) 
খোঁজে। আমরা প্রজেক্টে build-pages.js স্ক্রিপ্টটি যুক্ত করেছি যা নিচের ধাপগুলো সম্পন্ন করে:

ধাপ ১: Vinext বিল্ড সম্পন্ন করা
   - npx vinext build কমান্ডের মাধ্যমে Next.js App Router, RSC (React Server 
     Components), Client Bundles এবং SSR রানটাইম কম্পাইল করে dist/ ফোল্ডারে রাখে।

ধাপ ২: out ডিরেক্টরি তৈরি ও অ্যাসেট কপি
   - বিল্ডার out/ ফোল্ডার তৈরি করে এবং dist/client থেকে সমস্ত CSS, JS চাঙ্ক ও 
     পাবলিক অ্যাসেট সরাসরি out/-এ কপি করে দেয়।

ধাপ ৩: Pages Advanced Worker (_worker.js) সেটআপ
   - dist/server ফোল্ডারের সমস্ত সার্ভার হ্যান্ডলার ও মডিউলকে out/_worker.js/ 
     ডিরেক্টরির ভেতরে সাজিয়ে দেয়।
   - Cloudflare Pages Advanced Mode অনুযায়ী _worker.js/index.js স্বয়ংক্রিয়ভাবে 
     পেজের এজ ওয়ার্কার এন্ট্রি-পয়েন্ট হিসেবে কাজ করে।

ধাপ ৪: রাউটিং অপ্টিমাইজেশন (_routes.json)
   - out/_routes.json ফাইল তৈরি করা হয়:
     {
       "version": 1,
       "include": ["/*"],
       "exclude": ["/_next/static/*", "/favicon.ico"]
     }
   - ফলে সব স্ট্যাটিক ফাইল সরাসরি ক্লাউডফ্লেয়ারের গ্লোবাল CDN ক্যাশ থেকে 0ms-এ 
     সার্ভ হয় এবং ডায়নামিক পেজ ও /api/* রিকোয়েস্টগুলো সরাসরি _worker.js-এ যায়।

ধাপ ৫: wrangler.toml কনফিগারেশন
   - রুট ডিরেক্টরিতে wrangler.toml ফাইলটি Pages-এর জন্য নির্দেশ করে:
     pages_build_output_dir = "out"
     compatibility_flags = ["nodejs_compat"]

★ Cloudflare Pages ড্যাশবোর্ড সেটিংস:
   - Framework preset: None (বা Next.js Static HTML Export)
   - Build command: npm run build:cloudflare
   - Build output directory: out
   - Root directory: খালি রাখুন (বা /)
   - Environment variables: MONGODB_URI এবং MONGODB_DB


--------------------------------------------------------------------------------
অধ্যায় ৩: Cloudflare Workers-এ যেভাবে কাজ করে (Native Worker with Assets)
--------------------------------------------------------------------------------
Workers ট্যাবে ডিপ্লয় করার আর্কিটেকচারটি সম্পূর্ণ নেটিভ:

ধাপ ১: wrangler.jsonc রিড করা
   - Cloudflare Workers সরাসরি প্রজেক্টের wrangler.jsonc ফাইলটি রিড করে:
     {
       "name": "next-cloud-mongodb",
       "compatibility_date": "2026-09-08",
       "compatibility_flags": ["nodejs_compat"],
       "main": "vinext/server/fetch-handler",
       "assets": { "directory": "dist/client", "binding": "ASSETS" }
     }

ধাপ ২: বিল্ড ও ডেপ্লয় প্রসেস
   - বিল্ড কমান্ড npm run build:vinext চালানোর পর dist/client-এ ক্লায়েন্ট ফাইল 
     এবং dist/server-এ ওয়ার্কার বান্ডেল তৈরি হয়।
   - ডেপ্লয় কমান্ড npx wrangler deploy সরাসরি এই ডিরেক্টরি দুটি ক্লাউডফ্লেয়ারের 
     Workers নেটওয়ার্কে আপলোড করে দেয়। কোনো out ফোল্ডারের প্রয়োজন হয় না।

★ Cloudflare Workers ড্যাশবোর্ড সেটিংস:
   - Build command: npm run build:vinext (বা npm run build:cloudflare)
   - Deploy command: npx wrangler deploy
   - Version command: npx wrangler versions upload
   - Root directory: /
   - Environment variables: MONGODB_URI এবং MONGODB_DB


--------------------------------------------------------------------------------
অধ্যায় ৪: MongoDB Atlas এজ কানেক্টিভিটি (lib/mongodb.ts)
--------------------------------------------------------------------------------
সার্ভারলেস এজ রানটাইমে MongoDB কাজ করানোর জন্য lib/mongodb.ts ফাইলে বিশেষ কিছু 
অপ্টিমাইজেশন করা হয়েছে:

১. Direct Shard কানেকশন (directConnection=true):
   - এজ রানটাইমে DNS SRV লুকআপ অনেক সময় ধীরগতি বা ফেইল করে। তাই সরাসরি 
     MongoDB Atlas-এর প্রাইমারি শার্ডে সরাসরি কানেক্ট করা হয়।

২. নোড সকেট ক্যাশিং বাগ প্রতিরোধ:
   - সাধারণ সার্ভারের মতো মেমরিতে স্থায়ী কানেকশন ধরে রাখলে এজ আইসোলেটের ফ্রিজিংয়ের 
     কারণে ডেড সকেট সমস্যা হয়। তাই এখানে সার্ভারলেস-বান্ধব কানেকশন মেকানিজম রাখা হয়েছে।

৩. নেটওয়ার্ক ও পারফরম্যান্স টিউনিং:
   - tls: true — সিকিউর হ্যান্ডশেক নিশ্চিত করে।
   - family: 4 — শুধুমাত্র দ্রুতগতির IPv4 প্রোটোকল ব্যবহার করে (IPv6 লেটেন্সি বাদ দেয়)।
   - maxPoolSize: 1, minPoolSize: 0 — মেমোরি লিক রোধ করে।

৪. সম্পূর্ণ CORS সাপোর্ট:
   - /api/db-check এবং /api/items রুটে Access-Control-Allow-Origin: * হেডার 
     যুক্ত করা আছে।
   - ফলে আপনার Pages ফ্রন্টএন্ড (যেমন topmcqbd.pages.dev) থেকে এই Worker API-তে 
     সরাসরি ফেচ রিকোয়েস্ট পাঠালে কোনো ব্রাউজার CORS ব্লকিং হবে না।

অধ্যায় ৬: কমান্ড চিটশীট (Cheat Sheet)
--------------------------------------------------------------------------------
* লোকাল Next.js সার্ভার চালু করতে:
  npm run dev (লোকাল পোর্ট: localhost:3000 বা 3001)

* ক্লাউডফ্লেয়ার Pages-এর জন্য out ডিরেক্টরি সহ বিল্ড করতে:
  npm run build:cloudflare

* ক্লাউডফ্লেয়ার Workers-এর জন্য সরাসরি বিল্ড করতে:
  npm run build:vinext

* লোকাল ক্লাউডফ্লেয়ার Workers এজ রানটাইমে লাইভ টেস্ট করতে:
  npx wrangler dev --port 8787

* টার্মিনাল থেকে সরাসরি Workers-এ এক ক্লিকে ডেপ্লয় করতে:
  npm run deploy:vinext (বা npx wrangler deploy)

* টাইপস্ক্রিপ্ট টাইপচেকিং ভেরিফাই করতে:
  npx tsc --noEmit

- Pages এ চালালে: Build command হবে `npm run build:cloudflare` এবং Output হবে `out`।
- Workers এ চালালে: Build command হবে `npm run build:vinext` এবং Deploy command হবে `npx wrangler deploy`।
- দুই জায়গাতেই MongoDB Atlas পূর্ণ সক্ষমতায় কাজ করবে!
