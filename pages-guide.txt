--------------------------------------------------------------------------------
অধ্যায় ১: পটভূমি (কেন সাধারণ ধারণায় Pages-এ MongoDB চলে না?)
--------------------------------------------------------------------------------
ওয়েব ডেভেলপারদের প্রচলিত ধারণা হলো—Cloudflare Pages-এ MongoDB চালানো অসম্ভব। 
এর পেছনে অতীতে ৩টি শক্তিশালী কারণ ছিল:

১. TCP সকেট ব্লকেজ:
   - সাধারণ Cloudflare Pages Functions (যেমন /functions ফোল্ডার) মূলত HTTP 
     রিকোয়েস্টের জন্য অপ্টিমাইজড। এর রানটাইমে নোডজেএস-এর আউটবাউন্ড সকেট পোর্ট 
     ২৭০১৭ (MongoDB পোর্ট) ব্লক/ড্রপ থাকত। ফলে MongoServerSelectionError আসত।

২. DNS SRV ফেইলিউর:
   - mongodb+srv:// কানেকশন স্ট্রিং এজে রেজলভ হতে পারত না।

৩. বিল্ড আউটপুট মিসম্যাচ:
   - Pages বিল্ড করার সময় out ফোল্ডার চায়। কিন্তু আধুনিক Next.js ফুলস্ট্যাক 
     ফ্রেমওয়ার্কগুলো dist/ ফোল্ডারে বিল্ড তৈরি করায় Pages ফেইল করত।


--------------------------------------------------------------------------------
অধ্যায় ২: কেন এবং কীভাবে এখন Cloudflare Pages-এ MongoDB সফলভাবে কাজ করছে?
--------------------------------------------------------------------------------
আপনার প্রজেক্টে এটি সফলভাবে কাজ করার পেছনে ৪টি মূল টেকনিক্যাল উদ্ভাবন রয়েছে:

১. Pages Advanced Mode (_worker.js) — মূল চালিকাশক্তি:
----------------------------------------------------
* আমরা build-pages.js স্ক্রিপ্টের মাধ্যমে প্রজেক্টটিকে "Cloudflare Pages 
  Advanced Mode"-এ রূপান্তর করেছি।
* এটি dist/server-এর পুরো Next.js সার্ভার লজিক ও রুট হ্যান্ডলারকে 
  out/_worker.js/index.js ফাইলে কনভার্ট করে দেয়।
* এর ফলে Cloudflare Pages আপনার অ্যাপকে সাধারণ স্ট্যাটিক সাইট হিসেবে দেখে না, 
  বরং ব্যাকগ্রাউন্ডে একটি "ফুল-স্কেল Cloudflare Worker ইঞ্জিন" চালু করে দেয়! 
  অর্থাৎ নাম Pages হলেও ভেতরে বাস্তবে একটি ক্লাউডফ্লেয়ার Worker কাজ করছে।

২. nodejs_compat এবং ক্লাউডফ্লেয়ার নেটিভ TCP সকেট:
--------------------------------------------------
* wrangler.toml-এ যুক্ত করা হয়েছে: compatibility_flags = ["nodejs_compat"]
* ক্লাউডফ্লেয়ারের আধুনিক nodejs_compat মডেলে Node.js-এর স্ট্যান্ডার্ড net ও 
  tls মডিউল স্বয়ংক্রিয়ভাবে ক্লাউডফ্লেয়ারের নেটিভ connect() সকেট এপিআই ব্যবহার 
  করে।
* ফলে এজ নেটওয়ার্ক সরাসরি পোর্ট ২৭০১৭ দিয়ে MongoDB Atlas-এর সাথে আউটবাউন্ড 
  টিএলএস সকেট তৈরি করতে পারে।

৩. সার্ভারলেস-বান্ধব MongoDB আর্কিটেকচার (lib/mongodb.ts):
--------------------------------------------------------
সাধারণ কানেকশন স্ট্রিং এজে ফেইল করে, কিন্তু আমাদের mongodb.ts ফাইলে রয়েছে 
বিশেষ কনফিগারেশন:
  - directConnection: true — কোনো ধীরগতির DNS SRV লুকআপ ছাড়াই সরাসরি 
    Atlas-এর প্রাইমারি শার্ডে (ac-odtentf-shard-00-02.8onjvem.mongodb.net:27017) 
    কানেক্ট হয়।
  - family: 4 — এজ নেটওয়ার্কে IPv6-এর সম্ভাব্য ডিলে বা ব্লকেজ এড়িয়ে দ্রুততম 
    IPv4 রুট ব্যবহার করে।
  - tls: true — সিকিউর এনক্রিপশন নিশ্চিত করে।
  - maxPoolSize: 1, minPoolSize: 0 — সার্ভারলেস আইসোলেট যখন ফ্রিজ হয়, তখন 
    যেন কোনো ডেড সকেট হ্যাং হয়ে না থাকে। প্রতি রিকোয়েস্টে ফ্রেশ লাইটওয়েট 
    হ্যান্ডশেক তৈরি হয়।

৪. স্মার্ট ট্রাফিক কন্ট্রোল (out/_routes.json):
----------------------------------------------
* out ডিরেক্টরিতে স্বয়ংক্রিয়ভাবে _routes.json তৈরি করা হয়:
  {
    "version": 1,
    "include": ["/*"],
    "exclude": ["/_next/static/*", "/favicon.ico"]
  }
* এর ফলে:
  - সমস্ত স্ট্যাটিক অ্যাসেট (CSS, JS, Fonts) ক্লাউডফ্লেয়ারের গ্লোবাল CDN ক্যাশ 
    থেকে 0ms-এ সার্ভ হয় (কোনো সার্ভার খরচ নেই)।
  - আর সমস্ত ডায়নামিক পেজ ও /api/* রিকোয়েস্ট সরাসরি আমাদের _worker.js-এ 
    চলে যায় এবং ডাটাবেস অপারেশন চালায়।


--------------------------------------------------------------------------------
অধ্যায় ৩: প্রজেক্টে যুক্ত করা মূল ফাইলসমূহ ও তাদের কাজ
--------------------------------------------------------------------------------

১. build-pages.js:
------------------
বিল্ড অটোমেশনের প্রাণকেন্দ্র। এটি:
- npx vinext build রান করে Next.js কোড কম্পাইল করে।
- dist/client থেকে স্ট্যাটিক ফাইলগুলো out/ ডিরেক্টরিতে বসায়।
- dist/server থেকে সার্ভার হ্যান্ডলারগুলোকে out/_worker.js/ ডিরেক্টরিতে বসায়।
- out/_routes.json ফাইল স্বয়ংক্রিয়ভাবে জেনারেট করে।

২. wrangler.toml:
-----------------
Cloudflare Pages-এর কনফিগারেশন নির্দেশক:
  name = "next-cloud-mongodb"
  compatibility_date = "2026-09-08"
  compatibility_flags = ["nodejs_compat"]
  pages_build_output_dir = "out"

৩. package.json:
----------------
  "scripts": {
    "build:cloudflare": "node build-pages.js"
  }
Cloudflare Pages যখন npm run build:cloudflare চালায়, তখন স্বয়ংক্রিয়ভাবে পুরো 
আউটপুট প্রসেস সম্পন্ন হয়।

৪. lib/mongodb.ts:
------------------
সরাসরি Atlas শার্ডের সাথে কানেক্ট করার অপ্টিমাইজড সার্ভারলেস ড্রাইভার লজিক।

অধ্যায় ৪: Cloudflare Pages ড্যাশবোর্ড সেটিংস রেফারেন্স
--------------------------------------------------------------------------------

- Project Platform: Cloudflare Pages
- Framework preset: None (বা Next.js Static HTML Export)
- Build command: npm run build:cloudflare
- Build output directory: out

- Environment variables:
    * MONGODB_URI = আপনার MongoDB Atlas কানেকশন স্ট্রিং
    * MONGODB_DB  = next_cloud_db
